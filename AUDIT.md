# Разбор upstream и изменения

Источник: https://github.com/Timon2306/mimic-discord, коммит `58413fe`, версия 1.3.1. Просмотрены исходники, а не только README. Убедительных признаков намеренной кражи токенов в просмотренных исходниках не найдено. Это не анализ готовых upstream-бинарников и не сертифицированный аудит.

| Наблюдение в upstream | Изменение в Mimic Linux |
| --- | --- |
| `tauri.conf.json`: CSP выключен (`null`); HTML загружает Google Fonts | Ограниченный CSP, системные шрифты, без внешнего содержимого |
| `spoofer.rs`: общий `/tmp/mimic_spoofer`, удаление до старта; нет изоляции экземпляров | Закрытая папка пользователя, случайные каталоги 0700, lock на экземпляр |
| `sanitize_relative_path` удаляет опасные компоненты вместо отказа; кеш десериализуется без перепроверки | Отказ от небезопасного пути, проверка сети/кеша и перед spawn |
| При существующем файле по вычисленному пути upstream может перейти к его запуску | Всегда `create_new` собственного встроенного helper в случайном закрытом каталоге |
| Процессы останавливаются также по сохранённым числовым PID | Только владеющие `Child`-дескрипторы с kill/wait, без глобального kill PID |
| `start_spoofer` проверяет Running до регистрации задачи; Paused не блокирует новый старт | Общая блокировка start/stop/pause/resume, проверка незавершённой задачи |
| `stop_spoofer` может abort-нуть задачу через 300 мс | Кооперативная отмена и ожидание всей очистки |
| `resume_notify.notified()` может пропустить уведомление | Короткий опрос атомарных флагов, отмена работает и во время паузы |
| Поля конфига ограничены в основном UI; `cooldown_every_n_batches = 0` ведёт к modulo by zero | Полная backend-валидация, ограничение ресурсов и длительности |
| RPC handshake принимает неподтверждённый READY, `set_activity` игнорирует ошибки чтения/тайм-аут | Строгий READY, проверка nonce, ERROR, формата ответа и тайм-аутов |
| При подключении RPC не проверяются владелец сокета и UID сервера | Проверка типа/владельца без symlink и peer credentials |
| Fetch базы не ограничивает время/размер ответа; кеш и история пишутся неатомарно | Тайм-ауты, ограниченное потоковое чтение, атомарные приватные файлы |
| История записывает весь batch, включая неудачные запуски | Только запущенные, живые к концу и выдержавшие полный интервал активности |
| Linux helper меняет comm на человекочитаемое название игры | comm сохраняет basename исполняемого файла; без ложных обещаний совместимости |
| UI и README содержат «100% safe» и предположения об умножении часов | Ограничения объяснены явно; локальная история отделена от результатов Discord |
| Workflow публикует релиз при обычном push | Read-only CI; только сборка и артефакты, без автоматической публикации |

Сохранены MIT-лицензия и ссылка на автора. UI и ключевые модули Linux-версии существенно переписаны. Техническая безопасность здесь означает уменьшение конкретных рисков; гарантировать полную безопасность или отсутствие санкций аккаунту нельзя.

Справочные первичные источники:

- Discord RPC/IPC: https://docs.discord.com/developers/topics/rpc
- Tauri CSP: https://v2.tauri.app/security/csp/

## Уточнение о Linux — версия 0.2.0

Предыдущий вывод нашего форка, что без RPC доступны только восемь игр, оказался слишком строгим. Подсчёт меток `os=linux` в каталоге не отражает все правила, которые текущий клиент передаёт Linux-детектору. При изолированной проверке штатного детектора Linux 1.0.168 Windows-имена ELF-помощников сопоставились с ожидаемыми ID четырёх игр, без RPC и Wine. В версии 0.2.0 разрешены безопасные Windows-имена процессов, обновлён источник каталога и версия кеша. Серверный зачёт часов из этого результата не следует. Подробности: [docs/native-detection.md](docs/native-detection.md).
