# Распознавание Windows-имён Linux-процессами

Проверено 8 ноября 2026 на Arch Linux x86_64, Discord Desktop 1.0.168.

## Найденная причина ограничения

Версия 0.1.0 выбирала только исполняемые файлы с меткой `os=linux`. В публичном каталоге таких игр восемь. Это фильтр нашего загрузчика, а не доказанный общий предел распознавания официального клиента.

В публичном JavaScript текущего Discord GameStore сохраняет исполняемые правила разных ОС. RunningGameStore группирует их по командной строке и передаёт имена в штатный ProcessObserver; на этой границе поля ОС уже нет. Нативный модуль Linux умеет сопоставлять эти имена с путями процессов, даже когда имя оканчивается на `.exe`.

Источники, прочитанные без авторизации:

- [Публичный каталог Discord](https://cdn.discordapp.com/detectables/games-v1.json).
- [Публичный JavaScript клиента при проверке](https://discord.com/assets/web.72656029554c0370.js), функции GameStore и RunningGameStore. Файл клиента может обновляться.

Проприетарные исходные файлы и бинарники Discord в репозиторий не добавлялись.

## Эксперимент

1. В отдельном Node-процессе загружен уже установленный официальный `discord_utils.node` и воспроизведена инициализация наблюдателя, включая обязательный обработчик ошибок. Без него модуль пропускает сканирование — первоначальные отрицательные пробы были невалидны.
2. Наблюдателю передана проекция всего скачанного каталога, с группировкой имён по аргументам и отображением его числовых ID обратно в ID приложений.
3. Запущены четыре собственных безоконных Linux ELF-помощника с именами `factorio.exe`, `overwatch.exe`, `game/eldenring.exe`, `rocketleague.exe`. Использованы байты помощника нашего проекта, а не программы игр.
4. Проверено, что для каждого нашего PID наблюдатель вернул именно ожидаемый ID приложения, а не просто человекочитаемое название.
5. Помощники остановлены, отдельный диагностический процесс завершён. Рабочий Discord, его настройки и учётные данные не использовались и не изменялись.

Все четыре сопоставления успешны. RPC, Wine и окна не использовались. Полный результат с ID и SHA-256 входных файлов: [native-detection-results.json](native-detection-results.json).

Две предварительные проверки с отдельными правилами также подтвердили имена `factorio`, `overwatch.exe` и `game/eldenring.exe`, с окном и без окна. Оконный помощник в продукт не добавлен: он не требуется для найденного способа.

## Что включено в приложение

Версия 0.2.0 предпочитает безопасное Linux-имя, а при его отсутствии берёт безопасное Windows-имя без обязательных аргументов. Лаунчеры пропускаются. Запускается только встроенный Linux ELF. Из снимка 25 188 записей проверку проходят 25 187; процессными кандидатами стали 10 463 игры. Это не означает, что все они по отдельности проверены или будут зачтены сервером.

Кеш версии 0.1.0 отбрасывается при загрузке. Сетевые запросы по-прежнему выполняются только по кнопке пользователя; токен не нужен.

## Граница результата

Доказано локальное распознавание четырёх конкретных Windows-имён штатным Linux-детектором. **Не проверено начисление часов, значков или наград сервером Discord.** Это требует реальной сессии аккаунта и сравнения серверной статистики до/после её обработки. Таймер активности и локальная история такими доказательствами не являются.

Прочие версии Discord, контейнерная изоляция, исключения, неоднозначные одинаковые имена и изменения каталога могут повлиять на результат. Поэтому в UI используется слово «кандидаты».

## Воспроизведение

После сборки helper и скачивания публичного каталога:

```sh
python3 tests/probe-native-detector.py \
  --module /absolute/path/to/discord_utils.node \
  --catalog /absolute/path/to/games-v1.json \
  --helper /absolute/path/to/our/build/out/dummy \
  --output native-result.json
```

Нужны Node.js и установленный официальный модуль Discord. Диагностика читает модуль в отдельном процессе и не подключается к аккаунту. Работает вне изолированной среды, если та скрывает процессы или графическую сессию. Обёртка завершает только свой Node-процесс после получения результата: выгружать Electron-дополнение внутри другого Node-runtime ненадёжно. Никакой код или бинарник Discord в сборку Mimic не включается.
